# Медиа и внешние плееры

Контракт доставки отделён от каталога: [openapi-media.json](../openapi-media.json), 5 операций. Полный URL берётся из ответа `filelist`, а не вычисляется по ID фильма. Результаты ниже относятся к исследованию **31 октября 2026**.

| Источник ссылки | Ресурс | Наблюдаемый результат |
|---|---|---|
| `filelist?reason=play` → `convertedUrl` | `/hls/{bucket}/{asset}.mp4/index.m3u8` | 206, `application/vnd.apple.mpegurl`, воспроизведение HLS и перемотка в Chrome |
| Относительная ссылка из плейлиста | `seg-N-v1-a1.ts` | 206, `video/MP2T`; разрешать относительно URL плейлиста |
| Конвертированный download / simplified watch | `/{bucket}/{asset}.mp4` | 206, `video/mp4`, native video в упрощённом плеере |
| `updates/detail` → `convertedUrl` | `/dav/{bucket}/{asset}.mp4` | **403** в анонимной проверке; рабочая замена HLS не подтверждена |
| `filelist?reason=download` → `url` | `fsN…/videofiles/{encodedPath}` | 206, `application/octet-stream`, `Content-Disposition` |

## HLS и Range

Проверенный плейлист — VOD version 3, target duration 10 секунд, относительные TS-сегменты и завершающий `EXT-X-ENDLIST`. В образце не было `EXT-X-KEY` или отдельных дорожек; это не доказывает их отсутствие во всём каталоге.

В браузере проверены ручной запуск, пропуск преролла, видимый кадр, mute, перемотка и пауза. Преролл и его телеметрия относятся к отдельному рекламному сервису и не входят в контракт каталога. Начальный autoplay может требовать пользовательского жеста.

При проверке скачивания отправлялся `Range: bytes=0-65535`, читалось не более 64 КиБ. Это проверка транспорта, а не полного скачивания или декодирования файла. Для оригинала наблюдался `Content-Range: bytes 0-65535/5735981227`; `Content-Length: 65536` — размер диапазона. `Content-Disposition` содержит UTF-8 `filename*`.

У проверенных HLS-плейлиста и сегмента был `Access-Control-Allow-Origin: *`; у оригинала и progressive MP4 этого заголовка не было. Политика одного медиаресурса не определяет CORS для JSON API.

## URL и бинарные ответы

Передавайте возвращённый **полный URL** HTTP-библиотеке без декодирования и повторного кодирования. Путь оригинала может содержать percent-encoded байты старой кодировки и `%2F`, тогда как query `filename` — UTF-8. При генерации клиента проверьте обработку уже закодированных параметров пути и выбор медиахоста: path-item `servers` поддерживаются генераторами по-разному.

Для `video/*`, `audio/*` и `application/octet-stream` читайте байты, поток или `Blob`, а не текст. Наличие `format: binary` в OpenAPI само по себе не гарантирует правильную работу сгенерированного runtime. HLS-плейлист читается как текст.

Размер оригинала передаётся десятичной строкой. Виртуальная MP4-копия может иметь `size: 0`, `qualityType: "-1"`, `sizeText: "Convert"` и тот же `id`, что оригинал. Различайте варианты также по URL; нулевой размер не означает пустой файл.

## Контролы плеера

Play/pause, mute, громкость, seek, переход между сериями, раскрытие плейлиста, fullscreen и PiP реализованы обработчиками HTML video. Отдельных REST-операций для этих контролов нет. В коде найден переключатель аудиодорожек, но многодорожечный образец не получен. Сохранение пользовательского прогресса находится вне области описания.

## SMB/CNStart и Фильмоскоп

[external-players.json](external-players.json) описывает URI из HTML карточки: `.icon.smb[data-id]` и `.icon.filmoscop[data-id]`.

- CNStart: используйте полный `cnstart://…` из HTML. На не-Windows сайт меняет только схему на `smb://`. Адрес файлового сервера нельзя надёжно вывести из `Video.fs`.
- Фильмоскоп: `iptvvideo://{host}/ajax/filelist/{videoId}` с сохранением домена категории.
- `/ajax/log/samba/{id}` и `/ajax/log/filmoskop/{id}` — необязательные счётчики запуска, ответ `{status:0,errorText:""}`. Вызовы меняют статистику.

Внешние программы, URI-handler, SMB-доступ и оборудование не проверялись. Описание URI не подтверждает успешный запуск стороннего плеера.
