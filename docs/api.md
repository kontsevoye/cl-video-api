# API видеосервисов Ситилинка / Karelia

Проверка: **2026-10-31**, анонимные запросы с отдельными несохраняемыми сессиями, frontend **1.1.37**. Это восстановленный контракт сайта, а не официальная документация оператора. Изменения каталога, ссылок и поведения после этой даты возможны.

Область работы: все выявленные публичные функции просмотра, поиска, чтения контента и медиа; функции аккаунта, публикации/загрузка и модерация исключены. Актуальный статус и ограничения каждой области — [coverage.md](coverage.md), машинный источник — [coverage.json](coverage.json). Всего описано **47 операций**: 37 в [основном контракте](../openapi.json), 5 в [медиа](../openapi-media.json), 5 в [упрощённой версии](../openapi-simple.json).

## Основа и источники

| Раздел | Базовый URL | `Video.type` в проверенной выдаче |
|---|---|---|
| Фильмы | `http://video.karelia.pro` | `1` |
| Сериалы | `http://serial.karelia.pro` | `2` |
| Мультфильмы | `http://mult.karelia.pro` | `5` |
| Аниме | `http://anime.karelia.pro` | `3` |

Для каждого домена подходят общие маршруты карточек, поиска и файлов. Выдача каталога зависит от домена. Это не параметр `site` в URL одного общего API. Поле `type` оставлено числом: таблица не доказывает, что других значений нет.

Описание составлено по публичному JavaScript frontend **1.1.37**, HTML четырёх каталогов и анонимным HTTP-ответам. Отдельные Chrome-сценарии с временным профилем проверили навигацию, фильтры, поиск, комментарии и воспроизведение HLS с перемоткой. Сводка результатов и границы проверки находятся в [статусе покрытия](coverage.md).

## Транспорт, сессия и ошибки

Проверенные чтения работают без авторизации и без передачи cookie. Сайт выдаёт `PHPSESSID` с `HttpOnly`, но снимки не сохраняют его значение. `/auth/check?inFrame=` в гостевом запросе завершился HTML-формой входа на `https://auth.citylink.pro/login`. Авторизация, обмен сессионными cookie и доступ после входа не проверялись; не следует придумывать Bearer-токен или готовый login API.

Прямой HTTPS-вход на `https://video.karelia.pro/` ответил редиректом на HTTP. JSON-чтение с `Origin: http://localhost:3000` не вернуло `Access-Control-Allow-Origin`. Следовательно, беспроблемный доступ из чужого браузерного origin не установлен. Практический путь для собственного приложения — native/серверный HTTP-клиент или свой backend. Из HTTPS-страницы также мешает mixed content. Эти наблюдения не устанавливают CORS-политику каждого маршрута и каждого origin.

Обычный конверт ошибки приходит с **HTTP 200**:

```http
GET /ajax/video/999999999
```

```json
{"status": 1, "errorText": "Не найден"}
```

У успешных ответов `status: 0`, обычно `errorText: ""`. Неверные параметры и сломанные маршруты могут вернуть **HTTP 500 с HTML**, а неизвестные маршруты — редирект на обычную HTML-страницу. Клиент должен проверять HTTP-статус, конечный URL/редирект, `Content-Type`, затем JSON `status`. Отсутствие `video` или `videos` нельзя трактовать как пустую успешную выдачу.

Rate limit, срок жизни ссылок, схема кеширования для клиента и SLA не определялись. Не закладывайте агрессивные повторы 500. GET в этом приложении не всегда означает отсутствие изменений: отдельные GET меняют коллекцию или сохраняют прогресс, а чтение файлов может учитывать просмотры/скачивания.

## Каталог и пагинация

```http
GET http://video.karelia.pro/ajax/1
GET http://serial.karelia.pro/ajax/1?new
GET http://mult.karelia.pro/ajax/1
GET http://anime.karelia.pro/ajax/1?new
```

Альтернатива флагу `new`: заголовок **`X-Requested-With: XMLHttpRequest`**. Он отправляется jQuery сайта, проверен отдельно; в своём клиенте добавьте его явно.

Сокращённая структура ответа (другие примеры встроены в [OpenAPI](../openapi.json)):

```json
{
  "videos": [{"id": 49272, "title": "Али Джи: Кто я?", "type": 1, "converted": true}],
  "status": 0,
  "errorText": "",
  "isLastPage": false,
  "videos_count": 23268,
  "nextPageUrl": "/ajax/2?kp_from=0&kp_to=0",
  "urlParams": {"page": 1, "kp_from": 0, "kp_to": 0}
}
```

`page` начинается с 1. В проверенных полных страницах каталога 20 карточек. На далёкой странице 2000 вернулось `videos: []`, `isLastPage: true`; верхняя граница и параметр собственного размера страницы не установлены. Останавливайтесь на `isLastPage` или пустом массиве.

**Особенность serial/anime:** `/` и `/ajax/1` без `new` и без AJAX-заголовка перенаправились на `/updates`. Сервер **не сохраняет `new` в `nextPageUrl`**, поэтому raw-клиенту нужно сохранять этот флаг либо отправлять `X-Requested-With: XMLHttpRequest`. Chrome успешно загрузил вторую страницу без `new`, с AJAX-заголовком, и показал 40 карточек. Формируйте следующую ссылку с исходным доменом и проверяйте origin. Сохраняйте `html`, если нужны HTML-фрагменты.

## Фильтры

| Параметр | Формат / значения | Статус |
|---|---|---|
| `genres` | CSV ID, например `14,7` | В проверенной странице все 20 карточек содержали оба жанра: наблюдаемое AND |
| `country` | ID, например `198` = США | Один ID проверен; интерфейс выбирает одну страну |
| `qualities` | CSV: `2` = 720p, `3` = 1080p, `5` = 3D | `qualities=3` и `2,3` проверены; значения из HTML UI |
| `year_from`, `year_to` | Числа года | Диапазон 2000–2026 проверен в составном запросе |
| `kp_from`, `kp_to` | Число рейтинга Кинопоиска | `kp_from=7` проверен; `0` используется сервером по умолчанию |
| `sorting` | `created`, `year`, `like`, `kinopoisk`, `views` | Все значения в интерфейсе; `year` и `kinopoisk` проверены запросами |
| `sort_order` | `asc`, `desc` | Оба направления использованы в успешных запросах |
| `new` | Флаг присутствия, `?new` или `new=` | Для raw-каталога serial/anime сохранять на всех страницах либо отправлять AJAX-заголовок |
| `html` | Флаг присутствия | Меняет внутренний JSON-контракт на строки HTML |

```http
GET /ajax/1?genres=14&year_from=2000&year_to=2026&kp_from=7&qualities=3&sorting=year&sort_order=asc
```

Сервер вернул 741 совпадение в момент проверки. Ошибочный `qualities=1080` в том же запросе дал 500: разрешение не является ID качества.

[ui-dictionaries.json](ui-dictionaries.json) содержит отдельные словари жанров, стран и качества для четырёх каталогов: 31, 25, 23 и 39 жанров соответственно. Это снимок HTML меню, отдельный рабочий JSON-метод справочников не обнаружен. Примеры жанров: `14` комедия, `7` приключения, `21` анимационный; не переносите весь набор жанров одного домена на другой без проверки.

`modes` — активный CSV-параметр полного поиска: **1 название, 2 описание, 3 в ролях, 4 режиссёр, 5 дополнительно**. Проверены все пять и комбинация `3,4`; Chrome подтвердил выбор режиссёра и запрос `/ajax/search/1?modes=4&query=Нолан&html`. В `urlParams` встречаются также `letter`, `year`, `d3`, `online_only`, но отдельные активные контролы для них в исследованном современном UI не найдены; они не объявлены проверенными фильтрами. У ленты обновлений `year/type/country` нормализовались в `null`, а фильтрующих контролов в её HTML нет.

## Поиск между каталогами

```http
GET http://video.karelia.pro/ajax/search/1?query=Shrek
GET http://video.karelia.pro/ajax/search/1?query=Avatar&name[]=name&site=1
GET http://serial.karelia.pro/ajax/search/1?query=Chicago
GET http://anime.karelia.pro/ajax/search/1?query=Psyren
```

Параметры `name[]=name&site=1` найдены в автоподсказках интерфейса и проверены. Полный набор современного `name[]` и семантика `site` не установлены: не следует считать `site=1/2/3/5` переключателем категории. Для категории выбирайте домен, для полей полного поиска — описанный выше `modes`. Поиск актёров и режиссёров отдельно подтверждён режимами 3 и 4; простой поиск без режима не доказывает их охват.

Ответ расширяет пагинированный каталог полями `searchGenres` и `otherSites`. Поиск `Shrek` на `video` дал **0** результатов текущего каталога, но нашёл мультфильмы в `otherSites`. Поиск `Avatar` вернул 4 фильма и отдельные 3 результата сериалов. Элемент `otherSites` — собственная страница с `videos`, счётчиком и `site: {id, subdomain, title, type}`. Счётчик верхнего уровня не является суммой всех сайтов. В HTML-странице поиска встречается опечатка `nextPageUrl: /ajax/searh/2?...`; этот alias проверен и отдельно описан, но для новых клиентов предпочтителен `/ajax/search/{page}`.

`nextPageUrl` поиска сохраняет `query`, но может опускать `name[]` и `site`. Если их используете, переносите явно. Query кодируйте через библиотеку URL, особенно кириллицу, `&`, `+` и скобки.

Фильмографии — отдельные публичные страницы `/person/{id}/videos` и `/person/{id}/videos/director`. Их API: `/ajax/person/{id}/videos/{actor|director}/{page}`. ID берите из `actorsCache`/`directorsCache` или ссылки карточки. В ответ добавлены `person` и `mode`. UI использует `from_all_sites=1`; домен и `Video.type` всё равно надо сохранять. `nextPageUrl` режиссёрской выдачи может ошибочно содержать `actor`, поэтому клиент должен удерживать выбранную роль. Chrome-переход из карточки к режиссёру Джордану Дауни дал три произведения.

## Карточка и модель Video

```http
GET /ajax/video/49272
```

Структура ответа: `{status, errorText, urlParams, video, trailers, updates, comments, user_score, ...}`. `selections`, `moviecycles`, `other_users` присутствуют не у всех карточек. В проверенном ответе «Шрэка» (`id=4100`) были 2 подборки и 1 цикл. Карточка мультфильма разрешилась также через домен `video`, что поддерживает общий ID-space на этом примере; для обычной работы сохраняйте исходный домен результата.

| Группа | Поля |
|---|---|
| Идентичность | `id`, `oldId`, `title`, `originalTitle`, `type`, `year`, `pegi` |
| Описание | `description`, `info`, `company` |
| Люди | `actorsCache`, `directorsCache`: `id`, `name`, `kinopoiskPersonId`, счётчики |
| Классификация | `countriesCache`, `genresCache` |
| Постер | `image`, `imagePath`; в HTML встречается `/uploads/images/thumbs/...` |
| Рейтинги | `localIndex`, `localVotesCount`, `imdbIndex`, `imdbVotesCount`, `imdbId`, `kinopoiskIndex`, `kinopoiskVotesCount`, `kinopoiskId` |
| Доступность | `converted`, `hasRip`, `has720`, `has1080`, `has4k`, `has3d`, `filesCount`, `enableSmb` |
| Статистика | `seeCount`, `downloadCount`, `playCount`, `commentsCount` |
| Пользовательские признаки | `favourite`, `bookmark`, `liked`; гостевые значения не доказывают работу записей |
| Служебное | `user`, `approved`, `draft`, `folder`, `disk`, `fs`, `vipTopicId`, `trailerId` |
| Время | `createTime`, `updateTime`, `imdbLastUpdate`, `kinopoiskLastUpdate` |

Полная типизация — [OpenAPI](../openapi.json), модель `Video`. Учтены реально встреченные `null` у `originalTitle`, `user`, `imdbIndex`, `imdbVotesCount`, ID человека и других полей. `kinopoiskId` и `imdbId` передаются строками. `0` рейтинга может означать отсутствие оценки; это не валидированная оценка качества контента.

Даты приходят объектами вида `{"date":"2026-10-27 09:07:25.000000","timezone_type":3,"timezone":"Europe/Moscow"}`, а не ISO-строками. Разбирайте их с указанной временной зоной. Описание не объявлено гарантированно безопасным HTML; выводите его как текст либо очищайте HTML при необходимости.

`Video.convertedUrl` в каталоге часто пуст, иногда содержит MP4 `/dav/...`. Для воспроизведения запрашивайте **filelist**: сериализаторы карточки, обновлений и файлов дают разные URL.

## Сезоны, серии, качество и медиа

```http
GET http://anime.karelia.pro/ajax/filelist/49154?reason=play
```

Сокращённый реальный пример:

```json
{
  "status": 0,
  "errorText": "",
  "videoId": "49154",
  "data": [{
    "season": 1,
    "title": "Сезон 1",
    "files": [{
      "id": 468126,
      "trackingTime": -1,
      "filetype": 1,
      "season": 1,
      "episode": 1,
      "filename": "с001.Psyren_[01].mkv",
      "size": "1502640329",
      "qualityType": 3,
      "qualityTypeString": "1080p",
      "translation": "AniLiberty",
      "converted": true
    }]
  }],
  "title": "Сайрен",
  "proposeModeration": false
}
```

URL из примера опущены; примеры ответов с URL встроены в [OpenAPI](../openapi.json). `videoId` здесь **строка**. `files[].id` — ID файла; его нельзя подставлять вместо ID карточки. Сезон и серия передаются численно; у фильма наблюдались `season=0`, `episode=0`, пустое название группы. Не выводите эти поля из имени файла.

Плеер сайта выбирает `filetype === 1 && converted`. `convertedUrl` в `reason=play` — наблюдавшаяся ссылка `http://streamN.karelia.pro/hls/...mp4/index.m3u8`. `url` — оригинальный файл на `http://fsN.karelia.pro/videofiles/...`. В ответах обновлений `convertedUrl` оказался MP4 `/dav/...`, а `onlineUrl` — ещё одной ссылкой. Домены/хеши не надо конструировать самостоятельно.

`reason` в исходниках: `play`, `play_updates`, `download`, `studios`, пустая строка. Живые ответы проверены для `play`, `download`, `studios`. Вариант `download` добавил **виртуальную MP4-запись рядом с каждым оригиналом**: тот же `id`, `size: 0`, `sizeText: "Convert"`, `qualityType: "-1"`, URL конвертированной копии. Поэтому даже ID файла не уникален для отображаемой строки скачивания; используйте также URL/вариант. Размер оригинала — десятичная строка байтов, сохраняйте точность.

Озвучки:

```http
GET /ajax/files/studiolist/49272
GET /ajax/filelist/49272?reason=studios&studio=Дублированный
```

Первый запрос вернул `[{"id":56,"translation":"Любительский"},{"id":54,"translation":"Дублированный"}]` внутри `data`. В аниме `id` отсутствовал: `[{"translation":"AniLiberty"}]`. JS передаёт **название** озвучки в `studio`, не ID. Проверенные `studio` с названием и числом вернули полный список; надёжность серверной фильтрации не установлена. Отбирайте по `files[].translation` на клиенте, сохраняя сезон и серию.

Оригинальные URL содержат `%XX`-последовательности пути, не похожие на UTF-8, при этом `filename` query может быть UTF-8. Сохраняйте возвращённый URL целиком: декодирование и повторное кодирование всего адреса может его испортить. Не меняйте HTTP на HTTPS без отдельной проверки хоста.

**Проверено:** HLS-манифест, сегменты, воспроизведение кадра аниме после преролла, mute, перемотка и пауза в Chrome. Bounded Range-запросы HLS, MP4 и оригинала вернули 206; оригинал также вернул `Content-Disposition`. Полные видео не скачивались. **Особое ограничение:** возвращённая `/dav/...mp4` ссылка дала 403, хотя HLS/обычный MP4 работают. Для передачи используйте `filelist`-ссылку, а не URL из serializer updates по аналогии. Подробности и отдельный контракт — [media.md](media.md), [openapi-media.json](../openapi-media.json). DRM/ключи, внешние аудиодорожки и субтитры не появились в исследованном манифесте; их существование у других файлов не исключено. `additionalFiles` в доступных примерах пуст, поэтому непустая модель не придумана.

## Обновления, подборки и топы

`GET /ajax/updates/1` на `serial`/`anime` возвращает `files`, `isLastPage`, `nextPageUrl`, `urlParams`. Это обновления **файлов**, не список карточек. В raw-объектах нет родительского `videoId`, поэтому нельзя восстановить соответствие карточке только через `file.id`. С `?html` каждая запись — HTML-фрагмент со ссылками на карточку; этот режим может пригодиться для ленты новых серий. Собственный параметр размера страницы не установлен.

`GET /ajax/top/1` возвращает обычную страницу `videos`. Отдельный `/ajax/top30/{period}` — UI-виджет. Все пять значений `week`, `month`, `vote`, `kinopoisk`, `all` проверены HTTP-запросами и через Chrome. Без `html` пришли пустые массивы, поэтому этот маршрут нельзя описывать как `Video[]`. «Недавно в кино» имеет собственную выдачу `/ajax/new_in_cinema/{page}`; проверены фильмы и мультфильмы, а также переход из меню в Chrome.

`GET /selections` — HTML-каталог подборок, ссылки имеют вид `/selection/10?sorting=like`. Его пагинированные карточки доступны по `/ajax/selection/10/1`, где `selection` содержит название и изображения. `/ajax/selections/1` перенаправился на главную; не считать его JSON-каталогом подборок.

`GET /ajax/video/49272/selections` вернул 73 варианта с `selected: false`, включая не связанные с карточкой подборки. Для существующих связей смотрите `getVideo.selections` или отбирайте `selected=true`. Найденный в JS `/ajax/video/{id}/movie_cycles` перенаправился на главную; это не публичная страница цикла. Рабочий путь — `/movie_cycle/{cycleId}`, API — `/ajax/movie_cycle/{cycleId}/{page}`, с объектом `moviecycle`. Chrome открыл цикл 63 из карточки «Шрэка» и показал семь произведений. Параметры `sorting=year&sort_order=asc` сохраняют порядок по годам.

«Случайное» работает через `/rand`: сервер выдаёт три случайные карточки. В Chrome кнопка «Показать ещё» имела `display:none`; для нового набора нужно снова открыть/обновить страницу. Хотя в HTML остался `nextPageUrl` с `ids[]` и `/ajax/random/`, этот legacy API вернул 500 с любыми проверенными вариантами и не используется видимым продолжением. В OpenAPI он помечен `deprecated`, рабочая `/rand` описана отдельно.

## HTML-режим и комментарии

| Маршрут | Без `html` | С `html` |
|---|---|---|
| Каталог | `videos: Video[]` | `videos: string[]` |
| Карточка | `video`, `updates`, … | `data: string`, `video_id`, `converted` |
| Список файлов | `data: FileGroup[]` | `data: string` |
| Обновления | `files: UpdateFile[]` | `files: string[]` |
| Топ-30 | `top30: [[], …]` в снимке | `top30: string[]` |

Внешний `Content-Type` остаётся `application/json`. Смысл зависит от **наличия** флага. Не ожидайте, что `html=false` отключит его: используйте отсутствие параметра. OpenAPI использует пустую строку enum для безопасной генерации `html=`.

**Комментарии доступны гостям.** Начальная карточка `getVideo?html` содержит до 30 `.comment-wrapper`, даже если raw `getVideo.comments` пуст. Код берёт `time` у самого старого, последнего wrapper и передаёт `/ajax/comments/{videoId}/{time}`. Это Unix-секунды; курсор `1491991741` карточки 14294 вернул 30 старых комментариев. Без `html` это `{id, text, createTime, ip}`, с `html` — строки разметки с автором и следующим курсором. Chrome нажал «Показать ещё» и увеличил количество с 30 до 60. Произвольные `0`/будущие курсоры давали пустую выдачу, что и ограничило первоначальную проверку. IP из legacy-ответов обезличены; клиенту не следует их отображать или логировать.

Трейлеры: в JS сохранился обработчик `.video-element-trailers__list li[data-trailer-id]`, создающий iframe `http://trubatv.com/tools/config_video_old.php?id=...`. На исследованных карточках таких активных элементов нет, `trailers` пуст. Класс `video-element_with-trailers` сам по себе не доказывает наличие трейлера — он встречается у блока киноциклов/подборок. В реестре это **legacy_only**; успешное воспроизведение трейлера и непустой DTO не заявлены.

## Отображение, внешние плееры и упрощённый сайт

`GET /users/skin/{id}` и `/users/grid/{enable|disable}` — гостевые настройки через cookie и редирект, без аккаунта. Chrome сменил skin 7, получил `anime_day.css`, затем `grid/disable` и 20 строк классического списка. Плитка/список и темы описаны в основном OpenAPI; клиент должен сохранять cookie. Сужение навигации (`navigation` cookie), локальные состояния контролов, громкость, fullscreen/PiP и раскрытие сезонов не являются отдельными API: это клиентское поведение.

CNStart/SMB и Фильмоскоп используют URI из HTML, а не отдельный JSON-плеер: `cnstart://...`, замена схемы на `smb://` для не-Windows, и `iptvvideo://{host}/ajax/filelist/{id}`. [Машинное описание](external-players.json) фиксирует правила. Счётчики `/ajax/log/samba/{id}` и `/ajax/log/filmoskop/{id}` возвращают `{status:0,errorText:""}` и необязательны для клиента. Внешние программы и устройства не запускались.

Упрощённый `*.s.karelia.pro` — отдельный HTML frontend **v128** с каталогом `/`, страницами `/{page}`, поиском `/search`, карточкой `/video/{id}` и native MP4-плеером `/watch/{id}`. Его параметры (`genre`, `year`, `on_page`, `name[]`) отличаются от современного API. На четырёх доменах получен HTML; Chrome подтвердил страницу 2 и `<video controls src="...mp4">` с ответом медиа 206. `/ajax/filelist` на этом frontend редиректится на HTML, поэтому нельзя просто подменить base URL современного клиента. См. [openapi-simple.json](../openapi-simple.json).

## Вне области описания

Авторизация, история, рекомендации, избранное, закладки, подписки, прогресс просмотра, лайки, публикация комментариев и жалоб, загрузки, редактирование и модерация не описаны. Успешные контракты этих операций и права доступа не проверены. Наличие маршрута в публичном JavaScript не подтверждает доступность функции без авторизации.

## Использование OpenAPI

[Основной контракт](../openapi.json), [медиа](../openapi-media.json) и [упрощённый сайт](../openapi-simple.json) используют OpenAPI **3.0.3**. Их можно импортировать в Swagger Editor, Postman или генератор клиента. Репозиторий содержит описание API; SDK генерируется потребителем при необходимости.

CSV-фильтры передавайте строками: `genres=14,7`, а не повторными `genres=14&genres=7`. Флаги `html` и `new` задаются присутствием параметра. Кодогенерация не заменяет проверку `status` и типа payload. Для бинарных ответов и уже закодированных URL см. [медиа](media.md).

Во встроенных примерах массивы сокращены. Дополнительные поля разрешены, обязательные поля заданы консервативно, неизвестные структуры оставлены открытыми. CSRF-токены и служебные IP в примерах обезличены; значения cookie не публикуются. Примеры отражают данные на дату исследования.
