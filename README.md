# API видеосервисов Ситилинка / Karelia

Неофициальное описание API каталогов фильмов, сериалов, мультфильмов и аниме на `*.karelia.pro`. Поиск, фильтры, карточки, комментарии, сезоны и файлы, ссылки на HLS, MP4 и оригиналы.

Описание восстановлено по публичному сайту и анонимным запросам. Проект не связан с оператором и не предоставляет собственный видеосервис.

## Спецификации

| Контракт OpenAPI 3.0.3 | Что описано | Операций |
|---|---|---:|
| [openapi.json](openapi.json) | Четыре каталога: JSON API, HTML-страницы и гостевые настройки | 37 |
| [openapi-media.json](openapi-media.json) | Доставка HLS, MP4 и оригинальных файлов | 5 |
| [openapi-simple.json](openapi-simple.json) | Упрощённый HTML-сайт / Smart TV | 5 |

[Руководство с запросами и ответами](docs/api.md) · [Статус покрытия](docs/coverage.md) · [Медиа и плееры](docs/media.md)

Веб-документация на GitHub Pages показывает все три контракта в Swagger UI: параметры запросов, схемы и примеры ответов. Исходные JSON доступны для скачивания по тем же относительным путям. Спецификации можно импортировать в инструменты OpenAPI или использовать для генерации клиента.

## Текущий статус

Версия описания **0.2.0**, исследование от **31 октября 2026**. Описаны **47 операций** и **19 функциональных областей** с известными ограничениями. Современный frontend — **1.1.37**, упрощённый — **v128**.

В ходе исследования проверены анонимные HTTP-ответы, браузерная навигация и воспроизведение HLS с перемоткой. Скачивание проверялось ограниченными Range-запросами, внешние плееры и оборудование не проверялись. Legacy-трейлеры найдены только в коде. Авторизация, функции аккаунта, публикация, загрузки и модерация находятся вне области описания.

Это снимок наблюдаемого поведения, без гарантии полноты скрытых маршрутов или совместимости будущих изменений. Подробные ограничения по каждой области — в [статусе покрытия](docs/coverage.md).

## Как читать примеры

Начните с [руководства](docs/api.md), затем раскройте нужную операцию в Swagger UI: **Parameters** описывает запрос, **Responses** — ответы и их примеры. Если для операции нет сохранённого примера, интерфейс показывает образец по схеме; он не является записью реального ответа.

Запросы к сервису выполняйте своим HTTP-клиентом, например `curl`:

```sh
curl --header 'X-Requested-With: XMLHttpRequest' \
  'http://serial.karelia.pro/ajax/1'
```

Сервис использует HTTP; доступ к JSON из другого браузерного origin не подтверждён. Веб-документация показывает примеры без отправки запросов к сервису. Для вызовов из собственного приложения учитывайте CORS, mixed content и сетевую доступность у оператора.

## Локальный просмотр

Нужны Node.js **22.12+** и npm.

```sh
npm ci --ignore-scripts
npm run check
npm run docs
```

Откройте **http://127.0.0.1:4173/**. `npm run docs` собирает сайт и запускает локальный сервер; остановка — `Ctrl+C`. После изменения исходников перезапустите команду. Отдельная сборка: `npm run build`; результат — `dist/`.

Другой порт: `npm run docs -- --port 4174`.

## Публикация на GitHub Pages

После создания репозитория выберите **Settings → Pages → Source → GitHub Actions**. Workflow `.github/workflows/pages.yml` проверяет спецификации и собирает сайт на pull request; push в основную ветку `main` или `master` публикует его в Pages. Доступен и ручной запуск. Адрес опубликованного сайта появится в окружении **github-pages** и настройках Pages.

Workflow следует [рекомендованной схеме GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). Он устанавливает закреплённые зависимости через `npm ci --ignore-scripts` и загружает только `dist/`. В Git хранятся исходники, манифест и lock-файл; установленные зависимости и результат сборки игнорируются.

При обновлении API редактируйте JSON-спецификации, руководство и [реестр покрытия](docs/coverage.json), указывая дату и границы новой проверки. `npm run check` валидирует OpenAPI, соответствие покрытия операциям и локальные ссылки. Проверки сборки не обращаются к видеосервисам.
